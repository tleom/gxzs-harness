# DSH 0.2.1-rc.2 升级

## 版本边界

从 `dsh-v0.2.1-alpha.5`（`1517a4dbca0a2789ff1d41ba439600f8547d23fa`）
升级到 `dsh-v0.2.1-rc.2`（`687f282e8625c6b8d11ff58211a90524be2e4317`）。
已比较两个 Git 标签之间的 13 个提交、465 项文件差异，包含中间 rc.1。

主要上游变化为版本号、正式版 Cordis 依赖、新增 DeepSeek Search/Fetch API 和模型显示标签。
本地补丁直接修改的 15 个上游包源码树、26 类运行域源码保持一致；补丁仍须对 npm 发行包
执行锚点、幂等性和行为验证，不能只凭源码未变放行。

## 适配

- 工作区与部署 profile 的 DSH 包统一锁定 rc.2，Cordis 使用 4.0.5、Schemastery 使用 3.18.5。
- 精确版本 guard、Host 版本报告、原生客户端 release 校验同步更新；补丁算法不因版本变化而放宽。
- 新增 `web-deepseek-api` 显式禁用，继续使用已配置的平台 MCP 搜索能力。
- 前端先部署接受 alpha.5 和 rc.2 的兼容版本；两个版本都要求清单具备匹配的 release 身份。
- 本轮没有聊天、技能、MCP、凭据或用户卷的存储格式迁移，不需要删除这些数据。

## 全局资源保留

之前镜像重建暴露出两项部署遗漏：全局技能只存在于旧镜像临时层，自定义字体构建参数未传入。
全局技能现由部署持久目录保存，通过 `GXZS_GLOBAL_SKILL_HOST_DIR` 同时只读挂载到 Host 与
Sandbox 的 `/opt/workbench-global/skills`。计划调查容器继承此只读挂载，复制其他动态资源时跳过它。
已运行容器的挂载不匹配时返回待换代，必须 drain/fence 后重建；不会静默覆盖活跃容器。

沙盒构建必须明确传入 `WORKBENCH_FONT_IMAGE`。公共 CI 显式使用 `system-fonts`；生产使用
已核对的私有字体镜像。运行时校验逐个检查字体 SHA-256、总数及 generation，同时检查 Git。
私有技能和字体文件不提交 Git；它们的完整清单和持久目录必须作为部署资产保留。

更新技能时保留挂载根目录 inode，按文件原子更新；替换整个根目录需要重建挂载它的容器。
个人 home、workspace 和 env 卷继续沿用原卷。部署细节见 `deployment-environment.md`。

## 验证与发布门槛

1. 冻结安装、原生补丁检查、Harness 与 Manager 测试、前端测试/类型检查/生产构建。
2. 使用生产私有字体构建候选镜像，核对技能完整配套文件、字体、Git 和 Office 实际功能。
3. 原生新建、恢复、换代、计划调查容器均能读取全局技能；确认个人环境仍在。
4. 模拟服务按 Chat Completions JSON/SSE 协议运行，覆盖真实工具、队列、子任务、后台任务、
   定时任务、取消、断连与恢复。模拟 usage 是测试计数，不代表真实分词或费用。
5. 最新提交 CI 和独立审核通过后，按前端兼容版本、Manager、Owner 换代的顺序部署。
6. 部署后按每个 Owner 核对实际镜像、ready、挂载及文件清单，检查日志和资源回落。

有限时长模拟压力证明对应范围内的行为；不替代真实供应商认证，也不构成无限期稳定承诺。
本文件描述发布契约，实际部署与压力结果记录在本次验收报告中。
