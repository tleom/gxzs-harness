# 用户运行环境命名

后端从当前租户的 `sys_user.user_name` 取得稳定登录账号，通过 `account_name` 传给 Manager。
默认租户的容器为 `gxzs-host-admin`、`gxzs-sandbox-admin`，纯数字账号保留前导零。
其他租户使用 `gxzs-host-租户.账号` 和 `gxzs-sandbox-租户.账号`，点号分隔避免跨租户名称拼接冲突。
名称转小写；当前账号规则为 1～30 位英文字母、数字、下划线或短横线，首位是字母或数字。
账号不可变；Docker 名称冲突会拒绝创建，不能接管另一用户的容器。

`owner_id`、`workspace_id`、`generation`、`instance_id` 仍是身份、租户隔离和换代凭据的依据。
物理容器名单独保存在 `container_name` / `sandbox_name`，容器标签保留账号、所有者、工作区和逻辑实例。
换代必须等待任务、后台作业和设置写入结束，再停止旧环境、撤销旧凭据、释放同名容器。
同一换代请求可重复提交；旧代凭据不能访问新代。健康确认后才清理经过身份校验的已停止前代容器。

Host 和 Sandbox 都以 `gxzs` 用户运行，UID/GID 仍为 1000，HOME 为 `/home/gxzs`。
镜像保留旧 HOME 路径的兼容符号链接，已有环境中的绝对路径继续有效。
每个用户独占 `/workspace`；不再增加账号目录。已有技能、MCP、环境和宿主配置卷复用，
`sandbox_volume_prefix` 将存储卷和可读容器名称分开，新卷继续使用唯一工作区标识，
避免改名时误建空卷或复用其他工作区遗留的同名账号卷。

## 已有部署迁移

1. 核对数据库账号格式、大小写唯一性、租户及全部已登记工作区；保存当前镜像、Manager 状态和配置指纹。
2. 开启工作台维护入口，使用已有 `profile-upgrade` 屏障等待每个用户的原生任务结束。
   未结束的任务保持运行，不能为改名强行中断。已停止用户也必须登记维护屏障。
3. 更新 Manager 与 Host/Sandbox 镜像后，通过后端换代接口逐用户切换；普通 `ensure` 不会擅自重命名旧绑定。
4. 核验名称、`id`、HOME、SSH、权限、挂载卷、MCP/技能目录、健康状态和换代凭据；再开放工作台入口。

旧版后端不传 `account_name` 时仍可运行旧名称；已迁移用户再次换代时沿用已登记名称。
部署命名空间后续变化也不会重命名已有用户。管理员工具操作 Docker 时应读取 `container_name`
（旧记录回退 `instance_id`），不能假设逻辑实例 ID 就是物理容器名。

聊天文件重建是单独授权的维护动作，不是普通启动逻辑。只处理明确的聊天文件路径，
不删除用户账号、宿主数据库、设置、模型凭据、技能、MCP、个人环境或记忆。
工作区下旧的身份 UUID 目录仅在确认为空时删除；`/workspace` 保持为用户工作空间根目录，
会话仍使用原生的 `conversations/日期/会话 ID` 子目录。

运行验证方式见 [合成并发测试](../scripts/soak/README.md)。此测试使用本地模拟模型输出，原生工具实际执行。
